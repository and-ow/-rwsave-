# .rwsave 编辑器

浏览器里查看 / 修改《铁锈战争》(Rusted Warfare) 的 `.rwsave` 存档，
改完存成**新文件**，原存档不动。

整个文件夹可直接拷走使用，**只需要 Python**。

---

## 一、依赖

只有两个，都很轻：

| 依赖 | 版本 | 用途 |
| --- | --- | --- |
| Python | **3.8+** | 运行环境 |
| Flask | 任意版本 | 网页服务（唯一第三方库） |

安装 Flask：

```bash
pip install flask
```

`rwsave_inspector.py`（存档解析器）只用标准库，无需额外安装。

---

## 二、运行

### 方式一：双击 `启动.bat`（推荐）

把 `.rwsave` 文件放进 `saves\` 文件夹，双击 `启动.bat`，
浏览器会自动打开 <http://127.0.0.1:5000>。

也可以**直接把存档文件夹拖到 `启动.bat` 上**，它会读那个目录。

> 停止服务：关掉命令行窗口即可。

### 方式二：命令行

```bash
# 用默认的 saves/ 目录
python rwsave_web.py

# 指定自己的存档目录（可重复）
python rwsave_web.py --dir "D:/Android/data/com.corrodinggames/rts/files"

# 换端口
python rwsave_web.py --dir "D:/我的存档" --port 5001
```

## 三、四步操作

1. **选存档** —— 左侧列表点一个 `.rwsave`
2. **挑单位** —— 中间表格筛选（关键字 / 队伍 / 类别 / 血量），点一行
3. **改字段** —— 右侧按分组列出该单位的所有可编辑字段
4. **存新档** —— 右上角「保存为新存档」，产物写到独立目录，文件名带时间戳

### 常见玩法

| 想做什么 | 怎么做 |
| --- | --- |
| 满血 / 加血 | 改「当前血量」；或勾选多个单位 → 批量填 `max_health` |
| 无敌 | 打开「无敌」开关 |
| 传送 | 改「位置 X / Y」 |
| 归心 | 改「所属队伍」（⚠ 会影响游戏内归属逻辑） |
| 瘫痪 / 禁用单位 | 打开对应开关 |
| 改击杀统计 | 改「击杀数」「累计造成伤害」 |
| 造一队满血单位 | 筛选队伍 → 表头全选 → 批量把「当前血量」设为 `max_health` |

## 四、安全设计

1. **绝不覆盖原存档** —— 产物写到独立目录，文件名自动加 `_已修改_时间戳.rwsave`；
   重名自动加序号。

2. **保存后强制自检** —— 写盘后立刻重新解析 + 校验：
   - 产物能被完整解析（字节级对齐，剩余 0 字节）
   - 解压后长度与原档一致
   - 每个补丁点的值生效（**以字节逐位比对**）
   - 所有非补丁字节逐一保持不变

   任一项不过 → 删除产物并报错，绝不留下坏档。

3. **绝不改动变长字段** —— 字符串长度、数组个数、magic 等字段标为 🔒 只读
   并说明原因。内核在类型层面拒绝写入，不是写坏了才报错。

4. **编辑留痕** —— 改动先暂存在内存，表格里标黄显示数量，可一键全部放弃。

## 五、它是怎么做到的

采用**内存 splice**路线：

```
原始 rwsave → 内存对象树(带字节留痕) → 修改 → 内存 splice → 重新 gzip → 新 rwsave
```

关键洞察：**可编辑字段全部是定长标量**（f32 / i32 / bool / i8 / i16 / i64）。
定长意味着「改值不改长度」，所以只要知道每个字段的字节 offset，
直接原地打补丁即可 —— **不需要写任何序列化器**。

于是「未改动部分天然字节精确」：实测改 6 处字段，
解压后的 965773 字节里**只有 11 个字节变化**，其余逐一保持原值。

这也带来三个好处：

| 常见坑 | 本方案 |
| --- | --- |
| 浮点 `round(x,6)` 精度损失 | **不经过浮点文本往返**，直接写 4 字节 f32 位模式 |
| 迷雾图 / 内嵌 `.tmx` 变成摘要 | **一个字节都不碰**，原样 memcpy |
| NaN / Infinity 需要特殊编码 | 按 IEEE-754 位模式原样写入 |

## 六、文件说明

```
10-开源编辑器/
├── rwsave_web.py          Flask 服务 + REST 接口
├── rwsave_edit_core.py    编辑内核：字节留痕 + 补丁 + 写回
├── rwsave_inspector.py    存档解析器（字节级精确对齐）
├── 启动.bat               Windows 一键启动
├── saves/                 把 .rwsave 放这里（或用 --dir 指定别处）
└── web/
    ├── index.html         单页结构
    ├── style.css          暗色主题
    └── app.js             表格 / 筛选 / 字段编辑 / 批量 / 保存
```

### 复用而非重写

`rwsave_edit_core.py` **不重新实现任何读取逻辑**，而是给解析器装两层：

1. `TracingReader` —— 继承 `Reader`，覆写读取原语记录 `(offset, 字节数, 类型码)`；
2. `SinkDict` —— 临时替换模块里的 `OrderedDict`，在
   `u["current_health"] = r.float()` 赋值的那一刻，把刚读到的 offset 绑到这个字段名。

于是**字段 offset 是解析时顺手得到的**，不需要任何手写的字段顺序表
（那是最容易与上游失配的地方）。

## 七、已支持的数据结构（2026-10-14 补齐）

早期版本只在 6 个存档上验证过，遇到带 AI 或模组逻辑的存档会报
「布尔值非法」。现已按游戏源码补齐下列结构，**12 个真实存档全部解析成功**
（含 5 个此前打不开的）：

| 结构 | 说明 |
| --- | --- |
| `AIController` 状态 | **AI 队伍**在 `PlayerTeam` 之前多写一整段（策略节点、行为列表等）。队伍表里的 `is_ai_controller` 标志决定是否读取 |
| 5 种 AI 策略节点 | `BaseZone` / `UnitGroup` / `TransporterGroup` / `PlainZone` / `RallyGroup`，各自动态长度 |
| `MissionEngine` 触发器 | 1282 个触发器的大地图也能正确读出 |
| `UnitCommand` | 路径点指令，字段按协议版本分段（40/46/58/65/79/82） |
| `CustomUnit` 自定义变量 | 支持 bool / number / string / unit 及三种数组 |
| 运输单位 | `Dropship` / `Hovercraft` 等携带单位的单位 |

> 这些结构**几乎都是按版本号分段写入**的——同一个字段在不同版本里
> 可能存在也可能不存在。解析时必须严格按门槛读，跳过或多余读取
> 都会让后面所有字节错位。这也是过去报错的主要成因。

验证：12 个存档 **71 万个字段绑定零错位**，无修改往返 ROOT 逐字节一致。

## 八、已知限制

| 限制 | 说明 |
| --- | --- |
| 只支持 `formatVersion ≤ 96` | 与游戏版本对应，更高版本游戏本身也拒绝加载 |
| 变长字段不可编辑 | 见第四节，这是 splice 路线的固有限制 |
| 队伍资源（credits）暂不可编辑 | 属队伍段而非单位段，未纳入本轮范围 |
| 少量字段语义未完全确认 | 界面标 ⚠ 且默认隐藏（如 `is_alive` / `world_x`） |
| `missionStateVersion ≥ 7` 未覆盖 | 区域控制 / 传送门模式，遇到会明确报错 |

## 九、说明

本工具仅用于存档查看与分析研究，不修改任何游戏文件，不分发游戏资源。

存档格式的解析基于开源重构版 Rusted Warfare (RWX) 项目的反混淆 Java 源码。
